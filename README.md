# 강남역 점심 추천 봇

매일 11:30(KST)에 강남역 반경 800m 안의 식당 5곳을 랜덤으로 골라 `오점뭐` 채널로 보내고,
채널 사람들이 메시지의 버튼으로 투표해서 정한 식당을 S3에 기록합니다.
평일 18:00에는 `오저뭐` 채널로 야근 저녁 추천(식사 4곳 + 술집 1곳)을 같은 방식으로 보냅니다 ([저녁 추천](#저녁-추천-오저뭐)).
`우사기` 채널에 채팅을 보내면 우사기 봇이 채팅 내용에 맞춰 우사기 소리로 답하고, 하치와레가 그 뜻을 번역해 줍니다 ([우사기 채널](#우사기-채널)).
슬래시 명령(`/도움`, `/점심 추천`, `/멤버 추가` …)으로 추천을 부르거나 갑옷씨 멤버 등급을 관리할 수 있습니다 ([우사기 명령](#우사기-명령)).

```
EventBridge Scheduler (점심 11:30 매일 / 저녁 18:00 평일, Asia/Seoul)
   └─> RecommendFunction ── 카카오 로컬 API (주 1회 수집, S3 캐시)
          │               └─ 카카오 장소 페이지 (고른 5곳 대표 사진)
          └─> 디스코드 오점뭐 / 오저뭐 채널 (봇 계정이 직접 보냄: 식당 5곳 + 사진 + 최근 선택 + 버튼)
                 └─ 버튼(투표) ─> InteractionFunction (Function URL)
                                    └─> S3 votes/ (표) → 마감되면 latest/ + selections/{카테고리}/
```

## 메시지

디스코드의 컴포넌트 V2로 만든 한 장짜리 목록입니다. 이모티콘은 쓰지 않습니다.
메시지는 봇 계정(`우사기 봇`)이 봇 토큰으로 채널에 직접 보내서, 봇의 프로필 사진과 배너가 그대로 보입니다.

```
우라! 야하~
10월 24일 토요일 · 지난번 없음 · 투표 3/7      (작은 회색 글씨)
──────────────────────────────
주신당 강남점  (네이버 지도 링크)                [대표 사진]
한식 · 212m
2표 · 민지, 현우                              (작은 회색 글씨)
──────────────────────────────
… 5곳
패스 1표 · 서연
──────────────────────────────
[주신당 강남점] [밥심] … (식당 5개)
[패스] [투표 종료]
```

먼작귀의 우사기는 말을 하지 않아서 소리만 냅니다. 상황마다 소리의 모양(한 번 외치기, 같은 소리 두 번, 물결로 늘이기, 떨림 소리 뒤에 외치기 …)을 비중에 따라 하나 고르고, 그 안을 소리 조각으로 채워서 매번 다르게 냅니다. `!!`는 가끔만 나옵니다.

| 상황 | 소리 조각 | 모양 (괄호는 비중, X·Y는 서로 다른 조각) | 예 |
| --- | --- | --- | --- |
| 추천 | 우라, 야하, 야앗, 이얏, 와앗 | `X!`(3) `X X`(2) `X~`(2) `X! Y~`(2) `X… Y!`(1) `푸르르르… X!`(1) `X X!!`(1) | `우라!` · `야앗 야앗` · `이얏… 우라!` |
| 투표로 식당이 정해진 뒤 | 야하, 우라, 와앗 | `X!`(3) `X~`(2) `X X!`(2) `X! Y~`(1) `X!!`(1) | `와앗!` · `우라 우라!` · `우라! 와앗~` |
| 패스가 가장 많거나 아무도 투표하지 않고 끝난 뒤 | 후웅, 흐응 | `X…`(3) `푸르르르…`(2) `X… 푸르르르`(1) `X`(1) | `흐응…` · `푸르르르르…` |
| 버튼 오류 (누른 사람에게만 보임) | 하아, 후웅, 하 | `X?`(3) `X…?`(1) | `하아?` · `후웅…?` |

떨림 소리 `푸르르르`는 길이가 매번 조금씩 다릅니다 (`르` 3~5개). 추천 소리를 1000번 뽑으면 `!!`는 87번쯤 나옵니다.

- 메뉴는 카카오 분류의 가장 구체적인 단계를 보여 줍니다 (`한식 > 국밥` → `국밥`). 카카오 API는 메뉴 목록을 주지 않습니다.
- 사진은 고른 5곳의 카카오 장소 페이지에서 링크 미리보기용 대표 사진(`og:image`)을 가져와 썸네일로 붙입니다. 사진이 없는 장소는 카카오가 주는 지도 이미지를, 가져오지 못하면 글자만 보여 줍니다.
- 식당 이름은 네이버 지도 검색으로 연결됩니다. 네이버 검색 링크의 미리보기 그림은 네이버 지도 로고뿐이라 사진은 카카오 것을 씁니다.
- 문구와 소리 조각은 [`src/lunchbot/messages.py`](src/lunchbot/messages.py)에 모여 있습니다.

## 투표

메시지 하나가 그날의 투표입니다. 버튼은 식당 5개와 `패스`, `투표 종료`입니다.

- **한 사람 한 표:** 디스코드 계정마다 한 표이고, 다시 누르면 표가 바뀝니다. `패스`도 한 표로 셉니다.
- **누가 어디에 투표했는지 보임:** 누를 때마다 메시지가 바로 바뀌어 식당 아래에 `2표 · 민지, 현우`가, 정보 줄에 `투표 3/7`이 보입니다. 이름은 서버 별명 → 디스코드 표시 이름 → 아이디 순서로 씁니다.
- **끝나는 때:** 정원만큼 투표가 모이거나, 누구든 `투표 종료`를 누르면 끝납니다.
- **결과:** 가장 많이 받은 식당이 그날의 선택이 됩니다. 동점이면 동점인 식당 중 무작위로, 패스와 식당이 동점이면 식당을 고릅니다. 패스가 가장 많거나 아무도 투표하지 않았으면 선택 없이 끝나고 지난번 선택이 그대로 남습니다.
- **끝난 뒤 메시지:** 우사기 소리, `투표 끝 · 식당별 표 수 · 7명 중 6명 투표` 한 줄, 고른 식당 카드(투표한 사람 포함)만 남고 버튼이 사라집니다.
- **정원:** `VOTER_COUNT`로 정합니다 (예: `7`). `0`이거나 비워 두면 채널을 볼 수 있는 사람 수(봇 제외)를 자동으로 셉니다. 자동으로 세려면 개발자 포털 → Bot 탭 → **SERVER MEMBERS INTENT**를 켜야 하고, 셀 수 없으면 정원 없이(`투표 3명`) `투표 종료` 버튼으로만 끝납니다. 정원은 추천을 보낼 때 정해집니다.
- 표는 메시지마다 따로 셉니다. 같은 날 추천을 다시 보내도 메시지끼리 표가 섞이지 않습니다.

## 저녁 추천 (오저뭐)

점심과 같은 한 장짜리 목록과 투표를 쓰고, 야근 저녁에 맞게 이렇게 다릅니다.

| | 점심 (오점뭐) | 저녁 (오저뭐) |
| --- | --- | --- |
| 보내는 때 | 매일 11:30 | 평일 18:00 |
| 5곳 구성 | 식사할 곳 5곳 | 식사할 곳 4곳 + **술집 1곳** (마지막 자리. 반경 안에 술집이 없으면 식사 5곳) |
| 빼는 분류 | 술집, 간식 (`EXCLUDE_CATEGORIES`) | 간식, 구내식당 (`DINNER_EXCLUDE_CATEGORIES`) + **오늘 점심으로 정해진 식당** |
| 정보 줄 | `10월 24일 토요일 · 지난번 …` | `10월 24일 토요일 저녁 · 오늘 점심 …` (점심이 아직이면 `오늘 점심 없음`) |
| 카드 왼쪽 띠 | 노란 주황 | 남색 |
| 투표 정원 | `VOTER_COUNT` (비우면 오점뭐 인원) | `DINNER_VOTER_COUNT` (비우면 오저뭐 인원) |
| 결과 저장 | `latest/`, `selections/` | `dinner/latest/`, `dinner/selections/` (점심 '지난번'과 섞이지 않음) |

우사기 소리, 대표 사진, 투표 규칙은 점심과 같습니다. 점심과 저녁의 차이는 [`src/lunchbot/meals.py`](src/lunchbot/meals.py)에 모여 있습니다.

## 우사기 채널

`우사기` 채널(`USAGI_CHANNEL_ID`)에 사람이 채팅을 보내면 우사기 봇이 채팅 내용에 맞춰 우사기 소리로 답합니다. 우사기는 말을 못 하니 소리만 내고, 이모티콘이나 해석은 붙이지 않습니다.

| 채팅 | 답 예시 |
| --- | --- |
| 인사 (`안녕`, `출근`, `퇴근` …) | `야하!`, `야앗~`, `우라 우라~` |
| 질문 (`?`, `뭐`, `왜`, `어디` …) | 먼저 갸웃: `하?`, `후웅? 우라!` |
| 밥·술 이야기 (`배고파`, `점심`, `회식` …) | `우라!`, `이얏 이얏!` |
| 피곤함·슬픔 (`ㅠ`, `야근`, `피곤` …) | `후웅…`, `흐응~ 푸르르르…` |
| 웃음·칭찬 (`ㅋㅋ`, `귀여워`, `최고` …) | `야하 야하~`, `와앗!` |
| 짜증 / 놀람 (`짜증`, `헐`, `대박` …) | `이얏!`, `하아…` / `와앗!`, `하?!` |
| 우사기 소리 (`우라!`, `푸르르`) | 같은 소리로 받아침: `우라! 야하~` |
| 그 밖의 채팅 | 신난 소리 위주로 섞어서 |

- 두 가지가 섞인 채팅은 소리도 섞습니다 (`야근인데 배고파 ㅠ` → `후웅… 우라!`).
- 답 길이는 채팅 길이를 따라갑니다. `ㅇ` 같은 짧은 채팅엔 소리 하나, 긴 채팅엔 2~4개(40자 이내)이고, 채팅의 `~`, `!`, `…`도 조금 따라 합니다.
- 연달아 보낸 채팅은 끝날 때까지(1.5초 조용할 때까지) 기다렸다가 합쳐서 한 번에 답합니다.
- 보내기 전에 `우사기 봇 입력 중…`을 답 길이만큼(0.3~3초) 보여 주고, 답장 표시는 10번에 6번쯤만 답니다. 가끔 짧게 한마디를 따로 더 보내고, 바로 전과 같은 답은 하지 않습니다.
- 봇이 보낸 채팅과 입장 알림 같은 시스템 메시지에는 답하지 않습니다. 답할 때 사람을 멘션(알림)하지 않습니다.
- **채팅 내용을 읽으려면** 개발자 포털 → Bot 탭 → **MESSAGE CONTENT INTENT**를 켜고 `docker compose restart usagi`로 다시 띄웁니다. 꺼져 있으면 내용을 읽지 않고 무작위 소리로 답합니다(우사기 봇을 @멘션한 채팅만은 내용에 맞춰 답함). 어느 쪽으로 답하는지는 시작할 때 `docker compose logs usagi`에 남습니다.
- 어떤 채팅에 어떤 소리를 낼지는 [`src/lunchbot/chat.py`](src/lunchbot/chat.py)의 낱말 목록(`KINDS`)과 목소리(`VOICES`)에서 고칩니다.
- 채팅을 받으려면 봇이 디스코드에 계속 연결돼 있어야 해서, Lambda가 아니라 항상 켜 두는 서버(`usagi`)로 띄웁니다.

### 하치와레 (우사기 말 번역)

번역을 켜 두면(`/하치와레 번역 켜기`, 기본은 꺼짐) 우사기가 답하고 1~2초 뒤 하치와레가 웹훅으로 우사기 말의 뜻을 풀어 올립니다. 우사기 메시지에는 여전히 해석을 넣지 않고, 번역은 하치와레만 합니다.

| 채팅 | 우사기 | 하치와레 |
| --- | --- | --- |
| 채팅 | 우사기 | 하치와레 |
| --- | --- | --- |
| `ㅎㅇ` | `야하~` | "안녕안녕~"래! 오늘도 잘 부탁해! |
| `점심 뭐 먹지?` | `하? 야앗!` | "응? 밥!"라고 하네! |
| `야근인데 배고파 ㅠ` | `후웅… 야앗! 우라!` | "힘들었지… 고기! 먹자!"래! |
| `ㅋㅋㅋㅋㅋㅋㅋ` | `와앗 와앗 와앗 와앗!` | "재밌다 재밌다 재밌다 재밌다!"래~ 둘 다 너무 웃겨! |

- **소리 한 토막에 번역 한 토막:** 우사기 소리가 둘이면 번역도 두 토막이고, 번역 토막의 끝맺음(`!`, `~`, `…`, `?`)도 소리와 같습니다. 그래서 `야앗!` 한마디에 긴 문장이 붙지 않습니다. 같은 소리를 잇달아 내면 같은 말을 되풀이합니다(`흐응 흐응…` → "토닥토닥 토닥토닥…").
- 토막의 뜻은 우사기가 채팅을 어떻게 읽었는지(인사, 질문, 피곤함 …)로 고릅니다. 질문에 먼저 갸웃한 소리는 갸웃한 말("응?")로, 섞인 채팅이면 둘째 종류의 목소리로 낸 소리는 둘째 종류의 말로 옮깁니다.
- 번역이 켜져 있으면 우사기가 답할 때마다 번역합니다. 켜고 끄기는 누구나 `/하치와레 번역 켜기`, `/하치와레 번역 끄기`로 하고, 서버 전체에 하나입니다. 하치와레는 짧은 틀(`"…"래!`)로 전하고, 10번에 3~4번은 번역 뒤 따옴표 밖에 자기 생각을 한마디 보탭니다("오늘도 잘 부탁해!", "나도 배고파졌어…"). 따옴표 안의 번역은 소리와 토막 수가 그대로입니다. 4번에 1번쯤 채팅한 사람 이름도 부릅니다(알림은 가지 않음). 바로 전과 같은 번역은 하지 않습니다.
- 우사기 봇은 웹훅 메시지에는 답하지 않습니다 (하치와레와 끝없이 주고받지 않게).
- 웹훅이 실패해도 우사기 답은 그대로 나가고, 로그에 경고만 남깁니다.
- 문장은 [`src/lunchbot/hachiware.py`](src/lunchbot/hachiware.py)에서 고칩니다: 대화는 `MEANINGS`(종류별 토막)·`SOUNDS`(소리별 토막)·`COMMENTS`(하치와레 자기 생각), 추천은 `RECOMMEND`·`FACTS`, 투표 결과는 `RESULT`·`NO_RESULT`, 하치와레 생각은 `COMMENTS`(대화 종류별과 `lunch`·`dinner`·`won`·`none`), 명령은 `NOTICES`, 하치와레 말투는 `FRAMES`.

하치와레 웹훅 달기 (번역과 [우사기 명령](#우사기-명령) 안내에 함께 씀):

1. 하치와레가 말할 채널마다 채널 편집 → 연동 → 웹후크 → 새 웹후크. 이름(예: `하치와레 봇`)과 프로필 사진을 정하고 **웹후크 URL 복사**.
2. `.env`의 `HACHIWARE_WEBHOOK_URLS`에 주소들을 쉼표로 이어 넣습니다 (`주소1,주소2,…`). 예전 이름 `HACHIWARE_WEBHOOK_URL`(하나)도 함께 읽습니다. 이 주소만 있으면 누구나 그 채널에 글을 올릴 수 있으니 공유하지 마세요.
3. 서버를 새로 띄웁니다. `.env`를 바꾼 뒤에는 `restart`가 아니라 `up -d`여야 새 값을 읽습니다.
   ```bash
   docker compose up -d interaction usagi
   ```
4. `docker compose logs interaction usagi`에 `하치와레 웹훅 N개 (채널 …)`, `하치와레 웹훅 있음. 번역은 지금 꺼짐`이 나오면 됩니다. 봇은 주소마다 어느 채널 웹훅인지 읽어서 묶고, 지워진 주소는 뺍니다.
5. 번역을 쓰려면 아무 채널에서나 `/하치와레 번역 켜기`.

대화 번역은 우사기 채널 웹훅으로만 합니다. 다른 채널의 웹훅은 그 채널에서 쓴 우사기 명령의 안내에 씁니다.

**번역 설정은 우사기 말이 나오는 곳에 따라 둘입니다.** 꺼져 있으면 그곳의 우사기 말은 무엇이든 하치와레가 번역하지 않습니다 (`/도움`의 사용법만 예외).

| 설정 | 명령 | 누가 | 적용되는 곳 |
| --- | --- | --- | --- |
| 서버 전체 | `/하치와레 전체 켜기`, `/하치와레 전체 끄기` | 직장인 갑옷씨 이상 | 모두가 보는 채널: 우사기 채널 대화, 메뉴 추천과 투표 결과, 명령의 결과 안내 (기본 꺼짐) |
| 개인 | `/하치와레 번역 켜기`, `/하치와레 번역 끄기` | 누구나 (나에게만) | 내 `/우사기` 1:1 스레드 안 |

- 개인 번역만 켜면 내 1:1 스레드에서만 번역되고, 우사기 채널처럼 모두가 보는 곳은 서버 전체 설정을 따릅니다.
- 개인 설정을 정하지 않은 사람의 1:1 스레드는 서버 전체 설정을 따릅니다. 한 번 정하면 서버 전체가 바뀌어도 그대로입니다. `/도움` 맨 아래에 두 설정이 켜져 있는지 나옵니다.

**메뉴 추천 번역:** 서버 전체 번역이 켜져 있고 오점뭐·오저뭐에 하치와레 웹훅이 있으면, 추천 메시지와 투표 결과의 우사기 소리를 그 채널의 하치와레가 번역합니다. 메시지 머리말의 우사기 소리와 하치와레 번역은 한 토막씩 함께 만들어서(여는 말, 그날 상황, 닫는 말) 토막 수와 끝맺음이 같고, 매번 모양이 달라집니다.

| 언제 | 우사기 (메시지 머리말) | 하치와레 |
| --- | --- | --- |
| 점심 추천 | `야하~ 하? 우라!` | "드디어 점심~ 지난번은 'KFC 강남역점'? 골라 줘!"래! |
| 점심 추천 (+ 하치와레 생각) | `우라! 야하~ 우라~` | "점심이다! 지난번 'KFC 강남역점' 맛있었지~ 눌러 줘~"라고 하네! 나도 점심 같이 먹고 싶다… |
| 저녁 추천 | `후웅… 야하~ 와앗~ 이얏!` | "야근 힘들지… 점심 데는 뺐어~ 여기 봐 봐~ 먹고 힘내!"래! |
| 투표로 정해짐 | `와앗! 이얏!` | "농민백암순대! 가자!"래! |
| 아무것도 안 정해짐 | `흐응… 후웅…` | "다들 패스… 다음엔 꼭…"라고 하네! |

- 정해진 시각의 추천, `/점심 추천`·`/저녁 추천`, `docker compose run --rm recommend` 모두 해당합니다. `--preview`는 보내지 않으므로 번역도 하지 않습니다.
- 투표 중에 버튼을 누를 때는 번역하지 않고, 마감될 때 한 번만 번역합니다.
- 대화 번역처럼 10번에 3~4번은 따옴표 밖에 하치와레 자기 생각을 보탭니다 (점심 "나도 점심 같이 먹고 싶다…", 저녁 "오늘은 한잔도 괜찮겠다…", 정해짐 "농민백암순대 맛있겠다~", 선택 없음 "괜찮아, 내일 또 있어~").
- 웹훅이 실패해도 추천과 투표는 그대로 진행됩니다. 문장은 [`hachiware.py`](src/lunchbot/hachiware.py)의 `RECOMMEND`, `RESULT`, `NO_RESULT`에서 고칩니다.

### 1:1 대화 (`/우사기`)

`/우사기`를 쓰면 우사기 채널 아래에 나와 우사기 봇만 있는 비공개 스레드(`우사기 · 내 이름`)가 생기고, 우사기가 거기서 나를 불러 인사합니다 (알림이 와서 스레드를 바로 찾을 수 있음). 스레드 안에서는 우사기 채널에서와 똑같이 대화하고, 번역이 켜져 있으면 하치와레가 하치와레 프로필로 그 스레드에 번역합니다.

- 사람마다 스레드 하나입니다. 다시 `/우사기`를 쓰면 같은 스레드를 다시 열고(일주일 조용하면 보관됨), 스레드를 지웠으면 새로 만듭니다. 스레드는 `threads/{서버 id}.json`에 기록됩니다.
- 다른 사람은 초대할 수 없습니다. 다만 서버 주인·관리자처럼 '스레드 관리' 권한이 있는 사람은 비공개 스레드도 볼 수 있습니다.
- 봇 역할에 우사기 채널의 **비공개 스레드 만들기**, **스레드에서 메시지 보내기** 권한이 있어야 합니다 (기본으로 켜져 있음). 없으면 하치와레가 알려 줍니다.

## 우사기 명령

디스코드 슬래시 명령입니다. 채팅 입력창에 `/`를 치면 나옵니다.

| 명령 | 쓸 수 있는 등급 | 하는 일 |
| --- | --- | --- |
| `/도움` | 모두 | 내 등급으로 쓸 수 있는 명령과 사용법을 하치와레가 알려 줌 |
| `/우사기` | 모두 | 나와 우사기 봇만 있는 비공개 스레드에서 1:1로 대화 ([1:1 대화](#11-대화-우사기)) |
| `/점심 추천`, `/저녁 추천` | 모두 | 오점뭐·오저뭐 채널로 메뉴 추천을 바로 보냄 (정해진 시각의 추천과 같은 메시지) |
| `/하치와레 번역 켜기`, `/하치와레 번역 끄기` | 모두 | 내 `/우사기` 1:1 스레드의 번역을 켜고 끔 (개인 설정) |
| `/하치와레 전체 켜기`, `/하치와레 전체 끄기` | 직장인 갑옷씨 이상 | 모두가 보는 채널(우사기 채널, 메뉴 추천·투표 결과, 명령 안내)의 번역을 켜고 끔 (서버 전체, 기본 꺼짐) |
| `/멤버 추가 [사람]` | 행인 갑옷씨 이상 | 멤버가 아닌 사람을 행인 갑옷씨로 등록 |
| `/멤버 승급 [사람] [등급]` | 직장인 갑옷씨 이상 | 나보다 낮은 멤버를 내 등급까지 올림 (대장은 대장까지) |
| `/멤버 강등 [사람] [등급]` | 직장인 갑옷씨 이상 | 나보다 낮은 멤버의 등급을 내림 |
| `/멤버 삭제 [사람]` | 직장인 갑옷씨 이상 | 나보다 낮은 멤버를 멤버에서 뺌 |
| `/추방 [사람]` | 직장인 갑옷씨 이상 | 나보다 낮은 사람(멤버가 아닌 사람 포함)을 서버에서 내보냄. 우사기가 채널에 `우라!` (모두가 봄) |

**등급:** 행인 갑옷씨 → 직장인 갑옷씨 → 대장 갑옷씨. 자기 등급과 그 아래 등급의 명령을 쓸 수 있고, 멤버가 아닌 사람은 모두가 쓰는 명령만 씁니다.

- **서버 주인**은 등록하지 않아도 항상 대장 갑옷씨입니다. 다른 대장보다도 높아서 대장을 내리거나 뺄 수 있고, 아무도 서버 주인을 내리거나 내보낼 수 없습니다. 처음에는 서버 주인이 `/멤버 추가`로 시작합니다.
- 승급·강등·삭제·추방은 자기보다 낮은 등급에게만 됩니다. 봇에게는 쓸 수 없습니다.
- `[사람]`은 디스코드의 사용자 선택칸, `[등급]`은 세 등급 중 하나를 고르는 칸입니다.
- 멤버 목록은 서버마다 `members/{서버 id}.json`에 저장됩니다.

**답하는 방식:** 명령을 쓰면 우사기가 그 채널에 소리로 반응하고, 하치와레 번역이 켜져 있으면 이어서 그 채널의 하치와레 웹훅이 하치와레 프로필로 그 소리를 번역해 결과나 까닭을 알립니다. 소리와 번역은 한 토막씩 짝입니다 (예: `와앗! 야하~` → "#오점뭐! 점심 추천 갈게~"라고 하네!, 거절 `하? 흐응… 후웅…` → "응? **직장인 갑옷씨**부터야… 지금은 **행인 갑옷씨**…"래~, 추방 `우라!` → "@민지 나가!"래!). 둘 다 모두에게 보입니다. **번역이 꺼져 있으면 우사기 소리만** 나가고 하치와레는 말하지 않습니다 (그래서 거절 까닭도 나오지 않음).

- **`/도움`만 명령을 쓴 사람에게만** 보입니다. 웹훅 메시지는 '나만 보기'가 안 돼서, 도움말은 우사기 답 아래에 `하치와레` 이름을 붙여 함께 보여 줍니다. 번역이 꺼져 있어도 보여 줍니다.
- 하치와레 웹훅이 없는 채널에서는 우사기 답 아래에 하치와레 말을 붙입니다.

처음 한 번 준비:

1. 명령을 디스코드 서버에 등록합니다 (명령을 고쳤을 때도 다시 실행). `--preview`는 올릴 내용만 보여 주고, `--clear`는 모두 지웁니다.
   ```bash
   docker compose run --rm --entrypoint python recommend scripts/register_commands.py
   ```
2. `/추방`을 쓰려면 서버 설정 → 역할 → 봇 역할(`daggle`)에서 **멤버 추방하기** 권한을 켭니다. 봇 역할은 내보낼 사람들의 역할보다 위에 있어야 합니다 (디스코드 규칙). 권한이 없으면 하치와레가 그렇다고 알려 줍니다.
3. 명령의 클릭은 버튼과 같은 Interactions Endpoint URL(`interaction` 서버)로 오므로 버튼 처리 서버가 켜져 있어야 합니다.

`/점심 추천`, `/저녁 추천`은 우사기가 먼저 답하고, 추천 메시지는 그 뒤에 보냅니다 (식당 목록을 다시 모아야 하면 1분 안팎 걸림). 보내지 못하면 하치와레가 알립니다 (번역이 꺼져 있으면 쓴 사람에게 우사기의 `후웅…?`만).

## S3 구조

| 키 | 내용 |
| --- | --- |
| `latest/selection.json` | 가장 최근에 투표로 정해진 식당. 정해질 때마다 덮어씀 |
| `selections/{카테고리}/{YYYY-MM-DD}.json` | 카테고리별 선택 기록 (`한식`, `중식`, `일식`, `양식`, `분식` …) |
| `recommendations/{YYYY-MM-DD}.json` | 그날 추천한 5곳 |
| `votes/{메시지 id}/meta.json` | 그 메시지의 투표 정보 (날짜, 5곳, 정원, 우사기 소리, 지난번 선택) |
| `votes/{메시지 id}/ballots/{사용자 id}.json` | 한 사람의 표. 다시 누르면 덮어씀 |
| `votes/{메시지 id}/result.json` | 마감 결과. 처음 한 번만 써짐 |
| `members/{서버 id}.json` | 갑옷씨 멤버와 등급 ([우사기 명령](#우사기-명령)) |
| `settings/hachiware.json` | 하치와레 번역 서버 전체 설정 (모두가 보는 채널, 개인 설정을 안 정한 사람의 1:1 스레드). 없으면 꺼짐 |
| `settings/hachiware_people.json` | 하치와레 번역 개인 설정 (사람마다 1:1 스레드 켜짐/꺼짐) |
| `cache/restaurants.json` | 강남역 반경 안 식당 목록 캐시. 점심·저녁이 빼는 분류가 달라서 아무 분류도 빼지 않고 전부 모아 두고, 추천할 때 거름 (7일마다, 또는 설정이 바뀌어 캐시로 감당이 안 될 때 다시 모음) |
| `dinner/latest/…`, `dinner/selections/…`, `dinner/recommendations/…` | 저녁(오저뭐)의 기록. 점심과 같은 구조 |

- 투표로 식당이 정해지면 `latest`와 `selections/{카테고리}`에 **두 번** 저장됩니다. 투표한 사람과 식당별 표 수도 함께 남습니다.
- 선택 없이 끝나면 아무것도 저장하지 않고, 최근 선택은 이전 값이 유지됩니다.
- 카테고리는 카카오 분류의 두 번째 단계(`음식점 > 한식 > 국밥` → `한식`)를 씁니다.
- 점심이라 `술집`과 `간식`(빵집·케이크·아이스크림 같은 디저트) 분류는 추천에서 뺐습니다. (`EXCLUDE_CATEGORIES` 환경 변수로 변경)
- 저녁은 `간식`, `구내식당`을 빼고, 술집은 마지막 한 자리에만 넣습니다. (`DINNER_EXCLUDE_CATEGORIES` 환경 변수로 변경)

## 준비물

### 1. 카카오 REST API 키
1. [Kakao Developers](https://developers.kakao.com) → 내 애플리케이션 → 앱 추가
2. 앱 키에서 **REST API 키** 복사
3. 앱 설정에서 **카카오맵 사용 설정**을 켜기 (꺼져 있으면 로컬 API가 403을 반환합니다)

### 2. 디스코드 앱(봇)
메시지는 봇 계정이 봇 토큰으로 채널에 직접 보냅니다. 봇을 상시 실행할 필요는 없습니다.

1. [Discord Developer Portal](https://discord.com/developers/applications) → New Application
2. **General Information**에서 `APPLICATION ID`, `PUBLIC KEY` 복사. 여기의 `NAME`은 초대 화면과 앱 정보에 보이는 앱 이름입니다
3. **Bot** 탭에서 메시지에 보일 봇 이름(`USERNAME`), 프로필 사진, 배너를 정하고, Reset Token → 봇 토큰 복사
4. 아래 주소로 봇을 서버에 초대 (권한: 채널 보기, 메시지 보내기, 링크 첨부)
   ```
   https://discord.com/oauth2/authorize?client_id={APPLICATION_ID}&scope=bot&permissions=19456
   ```
   초대하면 서버에 앱 이름으로 된 봇 역할이 생깁니다. 역할 이름은 서버 설정 → 역할에서 바꿀 수 있습니다.
5. 디스코드 설정 → 고급 → 개발자 모드 켜기 → 추천받을 채널 우클릭 → **채널 ID 복사**

## 배포 전에 로컬에서 보내 보기

AWS 없이 이 컴퓨터에서 추천 Lambda와 버튼 처리 Lambda를 실행해, 실제 디스코드 채널에서 확인할 수 있습니다.
S3 대신 프로젝트의 `.local-s3/` 폴더에 저장합니다. [uv](https://docs.astral.sh/uv/)가 필요합니다.

### 1. `.env` 채우기

```bash
cp .env.example .env
```

`.env`를 열어 값을 채웁니다. 로컬 스크립트는 실행할 때 이 파일을 읽고, 명령줄에서 준 환경 변수가 있으면 그쪽을 씁니다.

| 이름 | 필요한 곳 | 값 |
| --- | --- | --- |
| `KAKAO_REST_API_KEY` | `run_local.py` (`--sample`이면 불필요) | 카카오 REST API 키 (준비물 1) |
| `DISCORD_BOT_TOKEN` | `run_local.py` (`--preview`면 불필요) | 봇 토큰 (준비물 2-3) |
| `DISCORD_CHANNEL_ID` | `run_local.py` (`--preview`면 불필요) | 점심 추천을 보낼 채널(오점뭐) ID (준비물 2-5) |
| `DINNER_CHANNEL_ID` | `run_local.py --dinner` (`--preview`면 불필요) | 저녁 추천을 보낼 채널(오저뭐) ID |
| `DISCORD_PUBLIC_KEY` | `serve_local.py` | 개발자 포털 **General Information**의 `PUBLIC KEY` |
| `CENTER_LAT` 등 | `run_local.py` | 선택. 아래 [설정](#설정-환경-변수) 표와 같음 |
| `VOTER_COUNT` | `run_local.py` | 선택. 투표 정원 (예: `7`). 비우면 채널 인원을 자동으로 셈 ([투표](#투표)) |
| `DINNER_VOTER_COUNT` | `run_local.py --dinner` | 선택. 저녁 투표 정원. 비우면 오저뭐 인원을 자동으로 셈 |
| `USAGI_CHANNEL_ID` | `usagi_bot.py` | 우사기 채널 ID. 이 채널의 채팅에만 답함 |
| `HACHIWARE_WEBHOOK_URLS` | `usagi_bot.py`, `serve_local.py`, `run_local.py` (선택) | 하치와레 웹훅 주소들, 쉼표로 구분 (채널마다 하나). 우사기 채널 것은 대화 번역, 오점뭐·오저뭐 것은 추천·투표 결과 번역, 모든 채널 것은 그 채널의 명령 안내에 씀 ([하치와레](#하치와레-우사기-말-번역)) |
| `LOCAL_S3_DIR` | `run_local.py`, `serve_local.py`, `usagi_bot.py` | 선택. 저장 폴더 (기본 `.local-s3/`) |

`.env`에는 비밀 값이 들어가므로 공유하지 마세요. `.gitignore`에 들어 있습니다.

### 2. 추천 메시지 보내기

```bash
uv run --python 3.12 --with boto3 scripts/run_local.py
```

| 옵션 | 설명 |
| --- | --- |
| `--dinner` | 저녁 추천을 오저뭐로 보내기 (식사 4곳 + 술집 1곳, 오늘 점심 식당 제외) |
| `--refresh` | 식당 목록을 카카오 API로 다시 수집 |
| `--no-buttons` | 버튼만 빼고 보내기 (목록과 사진은 그대로) |
| `--sample` | 카카오 API 대신 샘플 식당 11곳(저녁 술집 자리용 1곳 포함)에서 골라 보내기. 메시지 확인용이라 `KAKAO_REST_API_KEY`가 없어도 되고, 식당 캐시에는 저장하지 않습니다. 샘플 식당에는 사진이 없습니다 |
| `--preview` | 디스코드로 보내지 않고 보낼 메시지(JSON)만 출력. 식당 수집과 사진 가져오기는 실제로 하고, 그날 추천 기록도 저장합니다. `DISCORD_BOT_TOKEN`, `DISCORD_CHANNEL_ID`가 없어도 됩니다 |

옵션은 띄어서 하나씩 적습니다 (`--dinner --preview`). 모르는 옵션이나 따옴표로 한 덩어리가 된 옵션(`"--dinner --preview"`)이 오면 실수로 보내지 않도록 아무것도 보내지 않고 멈춥니다.

- 첫 실행은 식당 목록을 모으느라 1분 안팎 걸립니다. 목록은 `.local-s3/cache/`에 남아서 다음부터는 바로 보냅니다.
- 처음에는 로컬 폴더에 선택 기록이 없어서 정보 줄에 "지난번 없음"이 나옵니다.
- 실패하면 카카오나 디스코드가 돌려준 응답이 출력됩니다. 봇 토큰은 출력하지 않습니다.
- 디스코드가 `50001`(Missing Access)이나 `50013`(Missing Permissions)으로 거절하면, 봇이 그 채널의 서버에 초대돼 있는지와 채널에서 메시지를 보낼 권한이 있는지 확인하세요.

### 3. 항상 켜 두는 서버 띄우기 (도커)

버튼 클릭(투표), 우사기 명령, 우사기 채널 채팅에 답하려면 서버가 항상 켜져 있어야 합니다. 서버는 모두 도커로 띄웁니다 ([Docker Desktop](https://www.docker.com/products/docker-desktop/) 필요).

```bash
docker compose up -d
```

| 서비스 | 하는 일 |
| --- | --- |
| `interaction` | 디스코드 버튼 클릭(투표)과 우사기 명령 처리 (`scripts/serve_local.py`) |
| `tunnel` | `interaction`을 인터넷 주소로 이어 주는 [cloudflared](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) 임시 터널 |
| `usagi` | 우사기 채널에 채팅이 오면 우사기 소리로 답하는 봇 (`scripts/usagi_bot.py`) |

1. 터널 주소를 확인해서 개발자 포털 **General Information → Interactions Endpoint URL**에 넣고 저장합니다. 저장할 때 디스코드가 검증 요청을 보내므로 서버가 켜진 뒤에 넣습니다.
   ```bash
   docker compose logs tunnel | grep trycloudflare.com
   ```
2. 추천을 보내고 버튼으로 투표합니다. 추천도 도커로 보낼 수 있습니다 (`uv run … scripts/run_local.py`와 같음).
   ```bash
   docker compose run --rm recommend
   ```
   ```bash
   docker compose run --rm recommend --dinner
   ```
   보내지 않고 메시지만 보려면 `--preview`를 덧붙입니다 (옵션은 [2. 추천 메시지 보내기](#2-추천-메시지-보내기)와 같음).
   ```bash
   docker compose run --rm recommend --dinner --preview
   ```
3. 우사기 채널에 아무 채팅이나 보내면 우사기 봇이 답합니다. 채팅 내용에 맞춰 답하게 하려면 개발자 포털 Bot 탭의 **MESSAGE CONTENT INTENT**를 켜고 `docker compose restart usagi`를 실행합니다 ([우사기 채널](#우사기-채널)).

- 표와 결과는 `.local-s3/votes/`에, 정해진 식당은 `.local-s3/latest/`(저녁은 `.local-s3/dinner/latest/`)에 저장됩니다. 컨테이너와 호스트가 같은 `.local-s3/`를 씁니다.
- 임시 터널 주소는 `tunnel` 컨테이너를 다시 띄울 때마다 바뀝니다. 바뀌면 포털에도 다시 저장해야 합니다.
- 로그는 `docker compose logs -f interaction usagi`, 끄는 건 `docker compose down`입니다. 서버를 끈 채로 포털 주소를 두면 디스코드의 정기 검사가 실패해 주소가 지워지고 알림이 옵니다.
- 도커 없이 띄우려면: `uv run --python 3.12 --with pynacl==1.5.0 --with boto3 scripts/serve_local.py`, `cloudflared tunnel --url http://127.0.0.1:8787`, `uv run --python 3.12 --with discord.py==2.4.0 --with boto3 scripts/usagi_bot.py`를 각각 실행합니다.

## 배포 (AWS SAM)

```bash
sam build            # 네이티브 의존성 문제가 나면: sam build --use-container
sam deploy --guided  # KakaoRestApiKey, DiscordBotToken, DiscordChannelId, DinnerChannelId, DiscordPublicKey, AlertEmail, VoterCount, DinnerVoterCount, HachiwareWebhookUrls 입력
```

`AlertEmail`에는 Lambda 오류 알림을 받을 이메일을 넣습니다.

배포가 끝나면 두 가지를 해 주세요.

1. 출력의 `InteractionsEndpointUrl`을 복사해서
   개발자 포털 **General Information → Interactions Endpoint URL**에 넣고 저장합니다.
   (저장할 때 디스코드가 검증 요청을 보내므로 반드시 배포 후에 넣어야 합니다)
2. `AlertEmail`로 온 **AWS Notification - Subscription Confirmation** 메일에서 **Confirm subscription** 링크를 누릅니다.
   누르기 전에는 오류 알림이 오지 않습니다. 알림은 두 Lambda 중 하나라도 실행 중 오류(예외, 타임아웃)가 나면 옵니다.

우사기 명령을 아직 등록하지 않았다면 [우사기 명령](#우사기-명령)의 등록 명령을 한 번 실행합니다. 배포한 뒤에는 `/점심 추천`·`/저녁 추천`이 추천 Lambda를 따로 부릅니다.
우사기 채널 봇(`usagi_bot.py`)은 Lambda가 아니라서 템플릿에 없습니다.

## 테스트

```bash
# 식당 목록을 새로 수집하고 바로 추천 보내기
aws lambda invoke \
  --function-name <RecommendFunctionName> \
  --payload '{"refresh": true}' \
  --cli-binary-format raw-in-base64-out out.json && cat out.json
```

첫 수집은 카카오 API를 수백 번 호출해서 1~2분 걸릴 수 있습니다. 이후 7일간은 캐시를 씁니다.

로컬 단위 테스트 (Python 3.10 이상 필요, Lambda 런타임과 같은 3.12 권장):
```bash
uv run --python 3.12 --with pynacl==1.5.0 --with boto3 --with "moto[s3]" --with pytest pytest tests
```

환경 변수나 키는 필요 없습니다. 테스트가 가짜 값을 직접 넣고 카카오·디스코드·S3를 모두 가짜로 바꿔서, 외부로 요청을 보내지 않습니다.

uv 없이 돌리려면 Python 3.10 이상 환경에서 `pip install pynacl boto3 "moto[s3]" pytest`로 설치한 뒤 `pytest tests`를 실행합니다.
Python 3.9 이하에서는 `dict | None` 같은 문법 때문에 테스트가 시작되지 않습니다. macOS 기본 `python3`가 3.9일 수 있으니 `python3 --version`으로 확인하세요.

## 설정 (환경 변수)

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `CENTER_LAT`, `CENTER_LNG` | 37.497952, 127.027619 | 기준 좌표 (강남역) |
| `RADIUS_M` | 800 | 반경(m) |
| `PICK_COUNT` | 5 | 추천 개수 (최대 5, 버튼 한 줄 제한) |
| `CACHE_DAYS` | 7 | 식당 목록 재수집 주기 |
| `SEARCH_PREFIX` | 강남역 | 네이버 지도 검색어 앞에 붙는 지역명 |
| `EXCLUDE_CATEGORIES` | 술집,간식 | 점심 추천에서 뺄 카테고리 (쉼표 구분) |
| `VOTER_COUNT` | 0 | 점심 투표 정원. 0 이면 채널을 볼 수 있는 사람 수로 자동 (배포 파라미터 `VoterCount`로 넣음) |
| `DINNER_EXCLUDE_CATEGORIES` | 간식,구내식당 | 저녁 식사 자리에서 뺄 카테고리 (술집은 따로 마지막 한 자리) |
| `DINNER_VOTER_COUNT` | 0 | 저녁 투표 정원 (배포 파라미터 `DinnerVoterCount`) |

추천할 때마다 식당 목록 캐시를 지금 설정으로 다시 거르므로, 반경을 줄이거나 제외 분류를 늘리면 다음 추천부터 바로 반영됩니다.
반경을 넓히거나, 중심 좌표를 옮기거나, 빼던 분류를 다시 넣으면 캐시로는 감당이 안 돼서 식당 목록을 자동으로 다시 모읍니다.

점심도 평일에만 받으려면 배포 시 `ScheduleCron`을 `cron(30 11 ? * MON-FRI *)`로 지정하세요. 저녁 시각은 `DinnerScheduleCron`(기본 `cron(0 18 ? * MON-FRI *)`)으로 바꿉니다.

## 참고

- 비밀 값(카카오 키, 봇 토큰)은 Lambda 환경 변수로 들어갑니다. 봇 토큰은 봇을 통째로 조작할 수 있으니 더 엄격하게 관리하려면 SSM Parameter Store로 옮기세요.
- `scripts/create_webhook.py`는 예전 웹훅 방식용이라 지금은 쓰지 않습니다.
- 식당 사진은 카카오 장소 페이지의 링크 미리보기 정보를 읽는 비공식 방식입니다. 페이지가 바뀌면 사진이 빠질 수 있고, 그때도 추천은 글자만으로 나갑니다.
